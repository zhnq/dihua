# 将微信记录递给已有 Codex 会话

此 fork 基于 [ZHlovecat/dihua](https://github.com/ZHlovecat/dihua)，保留上游的微信分享、解析和其他目标应用功能。

## 使用

1. 从微信分享到递话，或在记录页点击「再递一次」。
2. 目标选择 Codex，在「目标会话」区域点击「更换」。
3. 搜索会话标题，或从最近更新的会话中选择，也可以点击「新建会话」。会话下方显示项目简称，悬停可查看完整工作目录；滚动列表可继续加载历史会话。
4. 返回确认窗，按需查看内容预览、填写本次附加说明。默认点击 **复制并打开会话**，进入所选会话后按 ⌘V，检查后按回车发送；也可在说明框中按 ⌘Enter 执行交接。
5. 如需实验性的 **直接发送到会话**，在右上角「转发选项」中开启，再返回确认窗执行。它通过 `codex queue` 提交请求，可能开始处理，也可能排队；「已排队」不表示分析已完成。

完成页支持「重新复制」和「打开目标会话」，这两个操作不会重新提交请求。会话搜索支持方向键与回车，Esc 可返回确认窗。

会记住最近一次成功选择的会话与方式。选择已有会话时始终显示确认窗，即使开启了「收到记录后直接递出去」。切回「新建会话」恢复原来的深链新建流程。

## 要求与文件位置

- 需要本机 Codex CLI；已有会话功能使用官方 `app-server` 的 `thread/list` / `thread/read` 接口。直接发送还需 CLI 支持 `queue`。
- GUI 不一定继承终端 PATH；递话也会检查 `~/.local/bin`、`~/.volta/bin`、`~/.cargo/bin`、`/opt/homebrew/bin` 和 `/usr/local/bin`。
- 仅列出本地保存、可读取的普通会话，不列出临时和已归档会话。不连接云端或远程执行环境。
- 文字、图片、文件及原始导出被复制到目标会话工作目录的 `dihua-inbox/wechat-*/`。发送前会重新查询工作目录，不更改目标会话原来的目录或项目指令。
- 每次投递创建独立副本，**副本不会随递话历史自动清理**，可以在项目目录中自行管理。
- 新建会话无需 CLI。CLI 不可用时仍可使用原来的新建入口。

## 结果与失败

- 「待粘贴」：目标会话已打开，提示词已写入剪贴板，需要用户粘贴、发送。
- 「已排队」：CLI 返回成功，后续处理进度在 Codex 会话中查看。
- CLI 失败不会改投另一个会话，也不会自动重试。发送超时可能是结果不明，先检查目标会话是否收到，再决定是否重试。
- `queue` 传递文字与本地副本位置，不把图片当作 API 附件上传。Codex 需要实际打开副本中的图片和文件。
- 目标目录不存在、复制失败、会话不可读时会报告失败；原始记录仍留在递话。
- 有内部正文的缩进嵌套记录会递归解析并保留层级；没有随微信导出提供的正文或媒体无法补全，超过 16 层或内层条数不符时会提示限制。

## 实现与验证

`src/main/codex.ts` 管理只读会话查询、批次复制和 CLI 排队。JSON-RPC 查询不恢复会话、不启动模型处理；排队使用参数数组调用 CLI，不经过 shell。`CodexConversationPicker.tsx` 提供按需展开的搜索与分页列表，确认窗管理本次说明、发送方式和交接反馈。

新增测试覆盖 JSON-RPC 握手与分页、超时及异常退出、附件字节保留、项目文件保留、链接与递归目录拒绝、无 shell 参数传递、手动交接与排队状态、失败不改投和不自动重试。

官方接口说明：[深链](https://learn.chatgpt.com/docs/app/commands#deep-links)、[会话接口](https://learn.chatgpt.com/docs/app-server)、[codex queue](https://learn.chatgpt.com/docs/developer-commands#codex-queue)。
